# RG CubeXX 刷 muOS 部署记录（2026-11-05）

设备：RG CubeXX（Allwinner H700 / sun50iw9，4×A53@1.8GHz muOS OC，973MB RAM，720×720 方屏）
系统：MustardOS 2606.0 "ANDROMEDA"（Buildroot，glibc 2.44，kernel 4.9.170，aarch64）
SSH：默认 `root/root`（muOS 官方默认是 root/muos，这台实际密码是 root），公钥已装
别名：`ssh cubexx`（192.168.1.149）

## 结论

**v0.3.2 linux-arm64 核心在 muOS 上完整可用**，全链路验证通过：
muOS 前端 → muxretro/launch.sh → RetroArch（GL 显示 + ALSA 音频 + udev 手柄）→
makecode_arcade_libretro.so → cubeland 开场画面正常渲染（fb0 截图确认）。

## muOS 系统注册机制（踩坑记录）

- **core.json 在内置存储** `/opt/muos/share/info/manifest/`，SD 卡的 `MUOS/info/manifest/` 只有 assign.json；
  但 launch.sh 规定 **SD 卡 core.json 存在且是合法 JSON object 时优先**，所以两边都放了同一份。
- ROM 目录名 = manifest 里的系统 name（`/mnt/mmc/ROMS/MakeCode Arcade`）。
- content 启动请求格式（`/run/muos/content`，9 行）：NAME / CORE 文件名 / ASSIGN / 空行 / 空行 /
  LAUNCH(=core.json 里 libretro.<id> 的 id，如 makecode-arcade) / R_DIR1 / R_DIR2 / ROM 文件名。
  前端进程退出后 frontend.sh 的 RUN_CONTENT_LOADER 检测到该文件就自动调 launch.sh 起游戏。
- **重启前端 = `kill $(pidof muxfrontend)`**（frontend.sh 是 while 循环守护，会自动拉起）。
  注意 pkill -f 会误杀自己的 ssh 会话（命令行里含匹配串）。
- 无头验证游戏画面：`dd if=/dev/fb0`（32bpp，720×1440 双缓冲，stride 2880），取前 720×720 转 PNG。
- RetroArch 退出用 `kill -TERM $(pidof retroarch)`，launch.sh 会自动收尾并恢复前端。

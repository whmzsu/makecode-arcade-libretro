## muOS 系统注册机制（踩坑记录）

- **core.json 有两份**：内置 `/opt/muos/share/info/manifest/`，SD `MUOS/info/manifest/`（出厂时只有 assign.json）。
  launch.sh 规定 **SD 卡 core.json 存在且是合法 JSON object 时优先于内置**，所以 install.py 两边都写——
  只写内置那份、或只手工复制一次，系统在重启/升级后都会"消失"。
- ROM 目录名 = manifest 里的系统 name（`/mnt/mmc/ROMS/MakeCode Arcade`）。
- content 启动请求格式（`/run/muos/content`，9 行）：NAME / CORE 文件名 / ASSIGN / 空行 / 空行 /
  LAUNCH(=core.json 里 libretro.<id> 的 id，如 makecode-arcade) / R_DIR1 / R_DIR2 / ROM 文件名。
  前端进程退出后 frontend.sh 的 RUN_CONTENT_LOADER 检测到该文件就自动调 launch.sh 起游戏。
- **重启前端 = `kill $(pidof muxfrontend)`**（frontend.sh 是 while 循环守护，会自动拉起）。
  注意 pkill -f 会误杀自己的 ssh 会话（命令行里含匹配串）。
- 无头验证游戏画面：`dd if=/dev/fb0`（32bpp，720×1440 双缓冲，stride 2880），取前 720×720 转 PNG。
- RetroArch 退出用 `kill -TERM $(pidof retroarch)`，launch.sh 会自动收尾并恢复前端。

## ⚠ ASSIGN：前端 UI 里必须手动分配一次核心（最大的坑）

只把核心和 core.json 装好，**在 muOS 前端里点游戏是起不来的**：点开系统目录里的任意卡带，
会弹出 `Assign` 对话框让你选 core，而列表里找不到 MakeCode Arcade。

### 根因：`extra` 字段把系统从 Assign 里隐藏了

我从 WASM-4 抄了 `"extra": 1` 进 core.json 条目。对照可正常分配的系统（Arduboy / PICO-8 /
TIC-80 / Vircon32 / 2048）——**全都没有 `extra` 字段**；而带 `extra: 1` 的 WASM-4 自己
也不出现在 Assign 列表里（它只能从 muOS 的"包管理器"里装）。所以：

- `extra` = 1 → 视为"外部附加包"，不进 Assign 选择器；
- 去掉 `extra` → 系统正常出现在 Assign 列表的 `Game Engine` 分组下。

### 正确的操作顺序（每台新机都要做一次）

1. 前端 → **选项（Options）→ 内容选项（Content Options）**，第一行会显示
   `内容核心：未分配 / Content Core: Unassigned`；
2. 按 A 打开 Assign 对话框 → 选命名空间分组 **Game Engine** → 选 **MakeCode Arcade**；
3. 之后进 Play → MakeCode Arcade 分类 → 点卡带就直接启动，不再询问。

也就是说：manifest 只能让系统"被看见"，**前端 UI 里的这次分配是独立的一次性动作**，
它由前端自己持久化（该状态不在 `MUOS/info/` 下任何 json 里）。

### 验证方式（无头）

前端绑定 `/dev/uinput`，可以用虚拟手柄直接驱动 UI 并 `dd /dev/fb0` 截图确认，
无需人工按键：`out/deploy/muos/pad.py`（注入 UP/DOWN/A/B）+ `shot.sh`（截 fb0 转 PNG）。

## 电源键单击无睡眠效果（2026-11-07 13:38 诊断）

**结论：功能完整实现，且 H700/RG CubeXX 硬件支持最深待机；是这台机器的
「Sleep Function」被设成了 Disabled（`settings/power/shutdown = -2`）。**

官方依据（muos.dev/tour/modules/muxpower）：短按电源键的行为由 Sleep Function 决定，
可选 `Sleep Until Wake`（睡到再按电源键）/ `Instant Shutdown` / 定时「先睡后关机」/
`Disabled`（什么都不做）；长按恒为关机。官方 Hotkeys 表写明
「Sleep Suspend / Wake — Press POWER once」。Quick Tips 特别点名 **RG CubeXX 属 H700 设备，
Sleep Until Wake 使用该硬件最深的待机（仅内存供电）**，且插充电器不会把它唤醒。

本机证据链（全部只读核查）：

1. `/opt/muos/share/hotkey/sleep.json`：`"SLEEP_SHORT": {"inputs": ["POWER_SHORT"]}`
   → 单击电源键**确实**绑定了睡眠。
2. `/opt/muos/script/mux/hotkey.sh`：`SLEEP_SHORT|SLEEP_LONG) SLEEP` → `SLEEP()` 调
   `/opt/muos/script/system/suspend.sh`。`muhotkey -L` 与 `hotkey.sh` 进程都在跑。
3. `suspend.sh` 读 `settings/power/shutdown`（本机 **-2**），主 `case` 里
   `-2) ;;` 是**空分支**，直接返回，屏幕/CPU/音频全都不动 → 观感就是「按了没反应」。
   对照：`-1)` = `SLEEP && RESUME`（Sleep Until Wake），`2)` = 直接 poweroff，
   正数 = 定时秒数。`sleep.json`/语言包里确有 `Sleep Until Wake`/`Instant Shutdown`/
   `Disabled` 三个标签。
4. 内核 `/sys/power/state` = `freeze mem`，支持挂起；`danger/state` = `mem`。
   `/opt/muos/frontend/mususpend` 二进制存在且完整 → 不是功能缺失。

修复：前端 Configuration → Power → Sleep Function → 选 **Sleep Until Wake**。
`shutdown` 文件时间戳是 11-05 20:52（装系统当天），同目录 `idle_sleep` 等仍是镜像
原始的 3 月 6 日 → 这一档是配置时设的，**不是镜像出厂默认**。

**13:49 用户在前端改完并实机验证通过**，回读 `shutdown=-1`（文件 mtime 13:49），
由此坐实档位映射：**`-2` = Disabled / `-1` = Sleep Until Wake**。前端改动会同步重启
`hotkey.sh` + `muhotkey`（PID 从 2211/2241 变为 3413/3432），无需手动重启服务。
当时电池 100% Full 但仍插着电，故睡眠仍走 userspace 分支；拔电后才是 H700 最深待机。

两个容易混淆的相邻设置：
- `idle_sleep=0`：空闲自动睡眠关闭（与按键无关）。
- `idle_display=120`：闲置 2 分钟只关背光/走屏保，**不是睡眠**。
- 插电时（本机当时 93% Charging、`axp2202-usb/online=1`）`suspend.sh` 走
  `FAKE_SLEEP=1` 分支：`mususpend --state userspace`，用户态等待、不进内核 `mem`
  待机，唤醒源是电源键/拔充电器/定时。官方所述「最深待机」在拔电时才成立。
- H700 设备一律设 `POWER_DEVICE=axp2202-pek`，走 userspace 后端（代码里对
  `rgcubexx-h` 有专门分支），不是漏实现。

## 重推公钥的两个坑

1. **系统换了 → host key 变了**，必须先 `ssh-keygen -R 192.168.1.137` 清 known_hosts，
   否则 `Host key verification failed`。
2. **`cat pub | ssh 'cat >> authorized_keys'` 会静默写空**（实测 `wc -c` = 0，
   stdin 在 askpass 密码认证模式下没送达远端）。改用**命令行内联**：
   ```bash
   PUB="$(cat ~/.ssh/id_ed25519.pub)"
   ssh ark@host "mkdir -p ~/.ssh && chmod 700 ~/.ssh && \
     echo '$PUB' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys && chmod 755 ~"
   ```
   （`chmod 755 ~` 是 ArkOS 系 sshd StrictModes 的要求。）

## ⚠ 已定位的坑：RetroArch 1.22.2 退出 SIGSEGV（**与本核心无关**）

**现象**：命令行 `retroarch -L <core.so> <cart>` 启动后按 SIGTERM / `--max-frames` 退出，
进程 rc=139（Segmentation fault）。

**排查过程与证据（结论：RA 侧通用问题）**

1. core dump 解析（设备无 gdb，自写 `tools/core_pc.py` 读 NT_PRSTATUS + NT_FILE）：
   崩溃线程 **PC 落在一个完全未映射的地址空洞**，且映射表里**已经没有核心库**
   → 是"核心库被 dlclose 之后仍有人跳进去"。
2. 空核心对照（`out/deploy/r36s-clone/empty_core.c`，只导出 25 个 ABI 函数、
   不调用任何 environ）→ **同样 rc=139**。⇒ 与核心实现无关。
3. 三台环境对照：
   | 环境 | 命令行 -L + SIGTERM |
   | --- | --- |
   | .137（R36S Clone 镜像） | **139** |
   | r36s `.81`（同镜像） | **139** |
   | cubexx（muOS，RA 同样是 1.22.2，完整配置） | **139** |
4. 但 muOS 上**用户通过前端实际游玩 3 局全部正常退出**（playtime 有记录，
   RetroArch 日志走到 `Unloading core symbols` 完整收尾）。

**结论**：RetroArch 1.22.2 在 `-L` 命令行模式下退出时的固有问题，崩在**视频/音频已释放、
前端已重新接管之后**的清理阶段，用户无感知。**不是本核心的 bug，也不影响正常游玩路径。**

顺带排除的假说（都测过、都不是原因）：`SET_VARIABLES` 空表指针、SRAM/memory 接口、
精简配置 vs 完整配置、gl vs null 驱动、位置参数启动（该版不支持，rc=1）。

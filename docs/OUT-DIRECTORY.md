# out/ 目录使用规范

`out/` 是本地工作目录，**整个目录被 `.gitignore` 排除、永不进 git**。
它只装两类东西：**过程产物**（构建输出、测试现场、临时脚本）和**本地缓存**
（工具链、校验工具）。规范的目的就一条：**随时可以整目录删掉重建而不心疼，
仓库和 CI 不依赖它。**

## 一、铁律

1. **已提交的代码不许读 out/ 里手工堆的东西**。唯一允许的 out/ 引用是
   `tools/` 脚本**自己写自己读**的运行时路径（见下表）——这些由脚本自管，
   别往里面手工塞东西，也别改路径。
2. **第三方游戏语料永不进库**（`carts63/`、`testcarts/`）。
3. **顺手写的通用脚本直接进 `tools/`**（起好名字、写好头注释），不要落在
   `out/` 里生根——out/ 里的脚本默认是"用完即弃"。
4. 命名带**主题+日期**（如 `dbg-vita-crash-1116/`），一个任务一个子目录，
   **不要在 out/ 根下散落散文件**。

## 二、目录结构

| 目录 | 放什么 | 保留期 |
|---|---|---|
| （根）脚本自管路径 | `pxt64/`（探针卡带）、`testcarts/`（语料）、`core_test_data/`（host 存档）、`toolwrap/`（zig 包装）、`ndk/`、`fuzz/`、`coverage/` | 随脚本重建，不手工维护 |
| `carts/` | 第三方游戏语料集（`carts63` 等） | 长期，不进库 |
| `tool69/` | tool69 `/opt/mca-work/bin/` 的本地镜像（收编版在 `tools/tool69/`） | 与 tools/tool69 同步 |
| `toolcache/` | 本地工具链与校验工具（actionlint、zig、NDK 等） | 长期 |
| `archive/` | 已完结任务的现场归档（调试取证、旧版本验收、实验线） | 30 天可清 |
| `release/` | 各版本发版验收时的下载与核对产物 | 保留到下个版本发出 |

## 三、归档与清理纪律

- 任务完结（bug 定案、版本发完、实验放弃）：现场目录移进 `archive/`，
  有价值的结论写进仓库 docs 或 `.workbuddy` 日志，**别只留在现场文件里**。
- `archive/` 超过 30 天、且结论已沉淀到 docs 的，整目录删掉不犹豫。
- 删之前 grep 一眼 docs/ 和 .workbuddy/ 日志里有没有引用该路径。

## 四、历史遗留

2026-11-18 之前 out/ 根下散落了约 130 个条目，已按本规范归档进
`archive/`；仓库侧同日收编了 `tools/tool69/`。凡在本规范之前生成的
现场，如需翻旧账去 `archive/` 找。
